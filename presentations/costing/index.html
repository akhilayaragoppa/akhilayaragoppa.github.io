What is the unit of billing?

The token is the unit of billing

  • Trimming 200 tokens across 1M conversations/month ≈ $600/month saved.

Block 4 · Embeddings

Input billed only

  • An embedding model returns a fixed-size vector — same size whether you send 1 token or 30,000. So providers charge for input only.
  • Also 1–2 orders of magnitude cheaper per token than chat models.
  • Bonus: the first N dimensions are themselves a usable embedding — truncate a 3,072-dim vector to 256 dims for free, graceful quality loss.
Block 4 · Reasoning tokens

Thinking is billed as output

  • A reasoning model generates internal "thinking" tokens before its visible answer — billed at the standardoutput rates.
  • Complete thinking often hidden — you get a summary but pay for the full count. The one modality you can't pre-count locally.

Block 5 · Pricing tiers

The pricing cliff

  • Every major lab has an inflection point — commonly ~200K input tokens in a single request — above which per-token rates jump.
  • Recurring shape: input roughly doubles, output goes up ~50%.
  • The higher rate applies to the entire request, not just the tokens above the line.
Block 5 · Why

Attention is quadratic

  • Self-attention: Compute scales as O(n²)
  • KV Cache size explodes
  • KV cache size ≈ 2 × n × d × L × (bytes per value)
    the 2 is for K and V, n is tokens, d is model dimension, L is number of layers.
  • Batching efficiency collapses
Block 6 · Cost Saving - 1

Prompt Caching

  • Send the same prefix (system prompt, tool defs, fixed document) every request → the provider stores the intermediate computation (KV cache) instead of recomputing.
  • A cache hit is cheaper and faster (lower time-to-first-token).

Block 6 · Cost Saving - 2

Batch / async APIs — up to 50% off

  • Submit a large set of requests, results back within 24h (usually 1–6h), at ~50% off input and output.
  • OpenAI: up to 50,000 requests / 200 MB per job. Anthropic: up to 100,000 requests per batch.
  • Ideal for bulk document processing, evals, embedding generation, labelling, moderation sweeps.
If real-time isn't required, batching halves the bill for zero quality loss. Stacks with caching.
Block 6 · Modality-specific optimisations

Cut units before they're billed

  • Audio: drop silences > 5s; speed up 1.25–1.5× (≈ 33% off, no quality loss); downmix to mono-channel.
  • Image: crop blank regions · resize to useful resolution · low/medium detail first · zoom or resend only relevant regions at high detail
  • Video: scene / delta frame extraction (OpenCV, PySceneDetect, FFmpeg, CLIP) instead of blunt 1-FPS — 5–20× less.
  • Embeddings: retrieve full-dim, store full vector + a 256-dim truncation for a cheap first-pass; re-rank.
  • Text: trim the system prompt · cache the prefix · summarise old history · constrain output · right-size the model.
Block 8 · Structural levers

Distillation & fine-tuning

  • Use a frontier model to generate high-quality labelled examples for your task.
  • Fine-tune a much smaller, cheaper model on that data — it matches the big model on that narrow task.
  • Reported: ~13.7× lower cost per successful extraction vs. the frontier model. Fine-tuning job itself ≈ a few dollars, ~20 min.
  • A mature-team move: you now own a model artefact to version and re-train.

Block 9 · Takeaway artefact

The cost-optimisation checklist

  • Measure first — log usage on every call; attribute cost per feature & cohort; set spend caps; know cost per conversation.
  • Reduce tokens — trim the prompt; summarise old history; constrain output; downscale media; stay under the cliff.
  • Reduce unit price — cache every stable prefix; batch anything not latency-sensitive; right-size the model; match reasoning effort; distil; truncate embeddings.
  • Re-evaluate — re-run your model/price comparison every quarter.
